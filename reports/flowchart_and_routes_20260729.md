## 三、未探索提升路线（按性价比排序）

### 路线1：融合选择器（GLM-agent + merged4-agent）⭐ 最高性价比
- **依据**：GLM agent 在 73 题对了而 merged4 错了；融合 oracle = 1146（+73 vs merged4 单独）。
- **做法**：对每题，用执行结果一致性/ORM 分数在 GLM-agent 修正 SQL 和 merged4 选择 SQL 间选。
- **预期**：1073 → 1100-1130（若选择器召回率 50-70%）。
- **成本**：低。两个系统的 SQL 都已有，只需写融合选择器。
- **风险**：低。无 gold 选择器可能引入损坏，需消融验证修坏率。

### 路线2：n8 池 + 更强选择器
- **依据**：n4 oracle=1223，n8 oracle=1251（+28）；选择器距 oracle 差 155。
- **做法**：n8 池 ORM 打分（需 GPU 空闲）+ 多源融合选择器。
- **预期**：1068 → 1090-1110。
- **成本**：中（n8 打分需 vLLM，GPU 被 GRPO 占）。
- **风险**：低。

### 路线3：JOIN 路径探查（E2 schema linking）
- **依据**：124 JOIN 差异题（74 漏 JOIN + 50 过度 JOIN）。
- **做法**：agent 主动探查外键路径，告诉模型正确 JOIN 路径。
- **预期**：+10-30。
- **成本**：中（需写外键探查 + LLM 修正 agent）。
- **风险**：低。

### 路线4：子查询分解
- **依据**：255 子查询失败题（52 题含多 SELECT 嵌套）。
- **做法**：MAC-SQL 式分解——把复杂问题拆成子问题逐步生成。
- **预期**：+10-30。
- **成本**：高（需写分解 agent + 多轮 LLM 调用）。
- **风险**：中。

### 90% 可达性
- 四条路叠加上限：融合(1146) + n8(+28空间) + JOIN探查(+30) + 子查询(+30) ≈ 1200-1230。
- **仍 < 90%（1381）**。要到 90% 必须换更强基座生成器（70B+ / 专门微调 EX>75%）。

## 四、推荐下一步
**路线1（融合选择器）**：零成本验证（两个系统 SQL 都已有），且 oracle 上限 +73 是最大的立即可得增量。
