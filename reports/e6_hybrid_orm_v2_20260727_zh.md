1. **数据隔离**：候选池（merged4model n4、bestofn ckpt-1000、qwen3 oof、agentar_32b）均为上游项目**在 train 划分上**预生成的候选；本次仅将其在 dev 数据库上只读执行（`mode=ro` sqlite，仅 SELECT，`fetchmany(5)`），用于排序特征。

## 三、全过程时间线

### 1. 起点与问题定义
基线 1324/1534（86.31%），失败 210 题。目标：在合规、不泄露前提下向 90% 推进。已知 merged-4-model n4 候选池对失败题的覆盖（oracle）为 68 题 → 混合上限 1392（90.74%）；扩展四池并集覆盖 79 题 → 上限 1403（91.46%）。**瓶颈不在候选覆盖，而在选择器与触发器。**

### 2. ORM v1 失败诊断（承接前序会话）
v1 ORM（llama.cpp 部署）全量替换仅 724–725/1534。根因：训练 cutoff_len=3072 截断长 schema prompt，导致反校准（分数在近 0/近 1 双峰）。上游已训练 **ORM v2**：cutoff 4096 + 结果条件化 judge prompt（问题+schema+候选 SQL+执行结果预览 → True/False），合并 BF16 权重。

### 3. 打分基础设施建设
- `attach_candidate_results.py`：只读执行每个候选 SQL 并附加前 5 行结果。
- `combine_k5_with_candidates.py`：把 k5 基线 SQL 插为候选 0，形成每题 17 候选的统一池。
- `score_candidates_with_orm_v2_vllm.py`：vLLM 打分，取第一个生成 token 的 top-10 logprobs 计算 P(True)/(P(True)+P(False))。
- 期间修复：PEFT/gptq 导入冲突（绕开，直接用合并权重）；HF 加载挂死（GB10 sm_12.1 超出 torch 支持上限，弃用 HF 路径）；vLLM 显存不足（清理残留的 XiYanSQL/llama.cpp 进程与僵尸 EngineCore）；`max_tokens=0` 参数报错；prompt 超长（每题共享 base prompt 头尾截断，保证同题 17 个候选共享 token 前缀）；开启 prefix caching 后吞吐约 5 倍提升，1534×17 候选约 75 分钟完成。

### 4. 选择规则评估（全部官方语义、全量 dev）
| 选择器 | EX | 结论 |
|---|---|---|
| 六源 hash 多数投票 | 1290 | 低于基线 |
| GBDT 特征 ORM（xgboost，5.8 万 train 样本） | 1011 | 不足 |
| ORM v2 全量替换（band） | 1091 | 灾难：对 GLM 系 k5 SQL 的风格偏置导致 271 题正确被误替换 |

### 6. 最终系统构建与验证
- 空结果/报错 25 题：以 ORM v2 band 规则（δ=0.1，组内按结果 hash 票数决胜）在 merged4 四模型候选中选择替换项（扩展四池打分反而降到 7 修复，故选择池限定 merged4 模型）。
- 官方评测确认：**EX 1333/1534 = 86.90%，JOIN EX 992/1140 = 87.02%，Valid 99.93%**，与离线模拟完全一致（+9/0）。

## 四、关键经验与失败教训

1. **ORM v2 的题目内排序能力强、跨题绝对校准弱**：失败子集上 top-1 召回 34/68（50%），band 规则 39/68；但因其训练数据只含 agentar/omnisql/qwen3 风格候选，对 GLM 系 k5 SQL 系统性低估（正确题上 20% 被错误替换）。按模型族加性校准（γ 偏移）无法挽回。
2. **结果预览只有 5 行**（`fetchmany(5)`）：>5 行的等价结果因行序不同被 hash 分为不同组，约影响 33 题，略微稀释 hash 决胜信号。
3. **GLM-5.2 API 注意事项**：短答案评判必须关闭 reasoning（`thinking: disabled`），否则 token 被推理耗尽、content 为空；客户端返回结构为 `{"response": ...}` 包装。
4. **vLLM on GB10**：prefix caching 的前提是同一问题的所有候选共享完全一致的 token 前缀——截断策略必须按问题统一（头+尾），不能按候选分别左截断。

## 五、后续方向（按预期收益排序）

1. **ORM v3**：在训练数据中加入 GLM 风格的 train 划分候选，消除跨族偏置；有望启用 margin 触发器，预期 +20~30 EX。
2. 失败子集选择率提升（当前 39/68 = 57%）。
3. 空结果题的语义级核查（15 题可覆盖中已修复 9，其余 6 题需要值接地而非排序）。
