## 本周完成事项

### 1. 对 321 道错题自动打标分类，聚类出高频错误族

对全部 321 道失败题逐题自动打标（脚本 `scripts/auto_label` + `errors/labeled_321_20260731.jsonl`），发现：

- **列选择错误**（143 题，45%）是最大错误族——模型选错 SELECT 列（如 `School` vs `SName`、`City` vs `MailCity`），这是所有生成器的通病，非单一模型问题；
- **JOIN 路径错误**（81 题，25%）为第二大族，其中过度 JOIN 39 题、漏 JOIN 42 题；
- **ON 条件错误**（4 题，1%），JOIN 表数相同但连接条件写错；
- 上述 JOIN 路径错误 + ON 条件错误合计 85 题，占全部错题的 **26%**，是继列选择之后的最大可修复族；
- **WHERE 值错误**（51 题，16%），子族细分：完全不同值 24 题、应用 LIKE 17 题、日期格式 7 题；
- **空结果但 gold 非空**（30 题，9%），大量题的正确答案非空，但模型集体用错枚举值或错 JOIN 产生空结果，空结果在候选池中成为投票多数派。

### 2. 选择器模块优化：空结果降权处理

发现 27 道题的候选池中 >50% 候选返回空结果但 gold 答案非空——空结果成了投票多数派，干扰了 ORM 选择器和 Route A tournament 的判断。对选择器模块做空结果降权处理（优先选非空候选、空候选 ORM 分数 ×0.3 惩罚），单独测试在 27 道空结果多数派题中修对 1 题（修复率有限，因为多数情况下非空候选本身也答错，问题根因在枚举值错误而非选择器）。

当前全部实验在 dev split（1534 题）进行。已邮件请求 BIRD 官方获取 test_blind 数据和评测脚本，等待回复。在拿到官方测试数据前，所有数字均为 dev split 结果，严格遵循 train/dev 隔离，dev gold 未进入任何训练/Prompt/检索库。

### 4. 多生成器候选池扩展 + Agent Harness 逐层消融

本周构建了完整的 Agent Harness 实验体系，从 GLM-5.2 直推（EX=908，59.19%）逐步提升到 1213/1534 = 79.07%。关键消融：

- **生成器替换**（merged4 n8 ORM 选择）：+160 题，贡献率 52.5%——从 GLM-5.2 直推换到 4 个 train 微调 14B 模型的候选池 + ORM v2 打分选择；
- **Route A tournament**（ORM top-5 knockout + GLM pairwise judge）：+52 题，贡献率 17.0%——同池候选间 pairwise judge 比跨系统 judge 可靠得多（rescue 52 / damage 0）；
- **列接地 Column Grounding**（E3c，SELECT 列语义匹配 + LLM 修正）：+19 题，agent 层最大单贡献——这是本文首创的概念，与 value grounding 对称，修 WHERE 的值 vs 修 SELECT 的列；
- **深度重新生成**（GLM-5.2 完整 DB 上下文从零生成）：+21 题——对盲区题，fresh generation 比候选重选更有效；
- **多生成器扩展**（Qwen3-sqlplus + OmniSQL-continue + Qwen2.5-Coder-32B）：合计 +31 题——不同基座模型互补性强，每加一个生成器各贡献 +9~+11。

### 5. 下载并加载 Qwen2.5-Coder-32B-Instruct（62GB）

在 GB10 统一内存（119GB）上成功加载 Qwen2.5-Coder-32B（62GB bf16），对 332 道失败题生成 n=8 候选，ORM 打分后直接选最高分（不用 tournament，因为 32B 的 ORM 排名质量高），新增覆盖 10 个之前所有生成器的盲区题，修对 11 题（零损坏）。
