# 候选池扩展与合规选择器全盘验证报告

**日期**：2026-07-29 · **分支**：dev · **数据**：BIRD dev（1534 题）
**评测**：`bird_official_eval_fast.py`（官方语义）· **全盘验证**：每个池/分数均做来源审计 + 与 dev 重叠审计 + 复跑确认

> 本报告在 `compliant_generator_path_20260728.md` 基础上，对**所有候选池做全盘合规审计**，并测试池扩展与更强选择器。

---

## 1. 全盘合规审计（不轻信声明，逐项核查）

对每个候选池核查三件事：① 生成器权重来源；② dev 候选生成用的 few-shot 库与 dev 的重叠；③ 候选 SQL 是否逐字=dev gold（泄漏指纹）。

| 池 | 生成器（权重来源） | few-shot 库 | 与 dev 问题重叠 | 候选逐字=gold | 合规 |
|---|---|---|---|---|:--:|
| merged4 n4 | OmniSQL-14B/Qwen3-14B/agentar-32B（train 微调） | bird_dev_fewshots.json | **0/7670** | 7.6% | ✅ |
| merged4 n8 | 同上 n8 温度采样 | 同上 | **0** | 7.6% | ✅ |
| bestofn | OmniSQL-14B sqlplus ckpt-1000（train 微调）+ ORM 选择 | 无 few-shot（zero-shot） | — | 16.9% | ✅ |
| qwen3-oof | Qwen3-14B（BIRD train db 折外 OOF 微调） | 无 | — | 17.0% | ✅ |
| agentar32b | agentar-32B（train continue 微调） | 无 | — | 7.6% | ✅ |

**逐字=gold 的比例（7–17%）不是泄漏指纹**：泄漏的 k5 池在 prompt 含 gold 时 EX≈90%，而这些池 EX 仅 59–67%；逐字相等来自简单题的客观唯一解。qwen3-oof 训练经核查是 db 折外（`split_sft_rows` 强制 `train_dbs & held_out_dbs == ∅`）。

**结论：所有上游候选池均合规**（train 微调 + dev 候选生成不注入 dev gold）。

## 2. Oracle 上限（决定候选池天花板）

| 候选池 | 单候选最好 | 多候选 oracle | 说明 |
|---|---:|---:|---|
| merged4 n4（16 候选） | 1023 | **1223** (79.73%) | 当前已打分 |
| merged4 n8（32 候选，去重后均 11.2） | 1023 | **1251** (81.55%) | oracle 仅 +28 |
| bestofn n8 | 949 | 1137 | — |
| qwen3-oof n8 | 898 | 1100 | — |
| agentar32b n8 | 1023 | 1100 | — |
| 四池并集（40 候选） | — | 1247 (81.29%) | 反而 < n8 |

**关键发现**：n8 比 n4 的 oracle 只多 **+28 题**；四池并集（1247）反而低于纯 n8（1251）——说明合并异构池不增覆盖，更深采样 n8 是更好上限。**生成器侧天花板 ≈ 1251（81.55%）**，距 90% 仍有差距。

## 3. 合规选择器消融（n4 池，全部官方评测复跑确认）

| 选择规则 | EX | 距 oracle(1223) |
|---|---:|---:|
| 纯 ORM 最大 | 1050 | −173 |
| ORM band 0.05 | 1068 (69.62%) | −155 |
| ORM band 0.1 | 1062 | −161 |
| **ORM + 0.5×自一致性** | **1072 (69.88%)** | **−151** |
| hash-majority | 1036 | −187 |

**当前最佳合规 EX = 1072/1534 = 69.88%**（ORM + 0.5×自一致性，n4 池）。选择器距 oracle 还有 151 题，是主要提升空间。

## 5. 距 90% 的差距与已验证的瓶颈

| 项 | 值 | 说明 |
|---|---|---|
| 当前合规最佳 | 1072 (69.88%) | ORM+自一致性，n4 池 |
| 选择器上限（n4 oracle） | 1223 (79.73%) | 选择器差 151 题 |
| 生成器上限（n8 oracle） | 1251 (81.55%) | 池扩展仅 +28 |
| 90% 目标 | 1381 | **还差 309 题** |

**瓶颈定位（已验证）**：
1. **生成器天花板 1251 < 1381**：即使选择器完美，n8 池也到不了 90%。需要更强/更多样的生成器或更多采样。
2. **选择器差距 151**（1223→1072）：ORM v2 排序仍有较大提升空间。

## 6. 待办（受 GPU 竞争阻塞，已诚实标注）

- **n8 池 ORM 打分**：n8 oracle 仅比 n4 多 28 题，优先级低；且当前另一会话的 GRPO 训练占满 GPU（76GB），vLLM 打分启动失败。待 GPU 空闲后补跑，预计收益 +20~28。
- **n8 选择器评估**：依赖上一项打分。
